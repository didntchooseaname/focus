# Client communication

Few channels, written when it matters, and always to the people named in the [[Rules of engagement]].

## Channels

| Purpose | Channel |
|---------|---------|
| Planned updates | Mail to the technical contact |
| Urgent issue | Phone call, then mail |
| Documents | Shared folder |
| Questions in testing | Mail, one question per message |

## Principles

1. Write what you need from the reader in the first line.
2. Give dates and times in 24 hour format with time zone.
3. Never include credentials in a mail body.
4. Keep a copy of every message in the engagement folder.

## Example mail

```text
Subject: Northwind internal, question on S4

Hello,
We found a host at 198.51.100.7 that is next to S4 but not listed.
Is it in scope? We will not touch it until you answer.
```

Routine reports use [[Status updates]]. A real problem uses [[Incident during a test]]. The final message is the [[Executive summary]].
